# غرفة الحوادث: موقع ورشة مسار الأمن السيبراني

> **النسخة المتصلة (Netlify + Supabase):** راجع [دليل الإعداد وحدود التنفيذ](docs/online-setup.md). أمر البناء `npm run build:online`؛ ينشر Netlify `dist-online/` مع Functions. بقية وصف التشغيل دون إنترنت أدناه تخص النسخة القديمة للطوارئ.

موقع ثابت (HTML وCSS وJavaScript عادي) لورشة «غرفة الحوادث» في نادي طويق بجامعة جدة. تحقيق جماعي في حادثة تصيّد خيالية على أربع مراحل (البريد، السجلات، الأثر والمؤشرات، الاستجابة والتقرير). لا خادم، ولا حسابات، ولا قاعدة بيانات، ولا تحليلات، ولا طلبات خارجية. كل البيانات خيالية.

> اقرأوا قسم «الحدود الصريحة» أدناه قبل أن تعتمدوا على أي رقم أو حماية.

---

## 1. ما الذي يفعله الموقع

| الشاشة | وظيفتها |
|---|---|
| الدخول | اختيار الفريق T1–T6 والمقعد ← رمز مثل `T3-2`. لا حسابات. |
| الأدلة | الملفات التسعة، مفتوحة للجميع، مع نسخ الملف وتنزيله (ونسخة لـ Excel لملفات CSV). |
| المراحل 1–4 | مهام بنجوم، تصحيح آلي، تلميحات (3 لكل مرحلة، كل تلميح يخصم نقطة)، حفظ تلقائي، إنهاء المرحلة. |
| وضع المرشد | برمز PIN: يقيّم ما كتبه الفريق في البنود المفتوحة ويُصدر **رمز النتيجة**. |
| لوحة المنسّقة (`board.html`) | لصق رموز النتائج، الترتيب، المكافآت، التنبيهات، وعرض الشاشة للجمهور. |
| الاختبار القبلي والبعدي | فردي برمز المشارك، والمخرج كتلة نصية قصيرة تُنسخ. |
| المصطلحات | تعريفات عامة قصيرة للمبتدئين. |

## 2. التشغيل على جهازك (لتجربته)

تحتاجون [Node.js](https://nodejs.org) (النسخة LTS). لا تحتاجون تثبيت أي مكتبة. افتحوا الطرفية في مجلد المشروع:

```
npm test          # الاختبارات الآلية
npm run build     # يبني مجلد dist/ (الموقع الجاهز للنشر)
npm start         # يبني ويشغّل الموقع على http://localhost:8080
```

(إن كان المنفذ 8080 مشغولًا: في ويندوز PowerShell اكتبوا `$env:PORT=8081; npm start`.)

**اختبار المتصفح الآلي** (يحتاج Chrome أو Edge): `npm run test:ui`.

## 3. النشر

الناتج الذي يُنشر هو **محتويات مجلد `dist/` فقط**. لا ترفعوا `private/` ولا `docs/` ولا `evidence/` ولا `tests/` ولا المشروع كله.

> **تحذير مهم:** `docs/mentor-key.md` فيه كل الإجابات. إن رفعتم المشروع كاملًا إلى مستودع GitHub عام فقد نشرتم المفتاح. انشروا محتويات `dist/` وحدها، أو اجعلوا المستودع خاصًا. (مجلد `private/` مستبعد من git تلقائيًا، لكن `docs/` ليس كذلك.)

قبل أي نشر:

1. شغّلوا `npm test` ثم `npm run build`، وتأكدوا أن الرسالة الأخيرة «اكتمل البناء». البناء يفشل ويحذف `dist/` إن وجد إجابة صريحة أو ملفًا خاصًا أو طلبًا خارجيًا.
2. افتحوا `dist/index.html` بنقرتين على الملف (من القرص) وتأكدوا أن الموقع يعمل.

### أ) Netlify Drop (الأسهل)

1. افتحوا صفحة Netlify Drop (ابحثوا عن «Netlify Drop»).
2. اسحبوا مجلد `dist` كاملًا إلى الصفحة.
3. تعطيكم رابطًا جاهزًا. لتحديث الموقع اسحبوا `dist` الجديد من جديد.

### ب) GitHub Pages

1. أنشئوا مستودعًا جديدًا فارغًا.
2. ارفعوا **محتويات** `dist/` (الملفات داخله، وليس المجلد نفسه) إلى جذر المستودع.
3. من إعدادات المستودع ← Pages ← اختاروا الفرع `main` والمجلد `/ (root)`.
4. انتظروا دقيقة ثم افتحوا الرابط الذي يظهر.

### ج) Cloudflare Pages

1. من لوحة Cloudflare ← Workers & Pages ← Create ← Pages ← رفع مباشر (Direct Upload).
2. ارفعوا مجلد `dist`.

> **تحققوا بأنفسكم** من شروط كل منصة وحدودها الحالية قبل الاعتماد عليها (الحصص، النطاق، الخصوصية). لم أتحقق منها، ولا أفترض أنها ثابتة. الموقع لا يحتاج أي ميزة خاصة من المنصة؛ أي استضافة ملفات ثابتة تكفي.

## 4. ملفات الإعداد (كلها قابلة للتعديل ثم `npm run build`)

| الملف | ما فيه |
|---|---|
| `config/scoring.json` | النقاط: ★=1 ★★=2 ★★★=3، التلميح −1، المحاولتان الخاطئتان المجانيتان، خصم كل محاولة خاطئة بعدهما، درجات المرشد، حدود تنبيهات اللوحة. **مقترحة ولم تُجرَّب بعد؛ عدّلوها بعد البروفة.** |
| `config/settings.json` | `stageRelease` (`"team"`: يفتح الفريق المرحلة التالية بنفسه، `"code"`: تعلن المنسّقة رمز فتح كل مرحلة)، قائمة الفرق، عدد المقاعد، `RESULTS_FORM_URL` و`RESULTS_ENDPOINT` (فارغان). |
| `config/synonyms.json` | قاموس المرادفات للأسماء وأركان CIA ونعم/لا وأنواع الضوابط (يمكن توسعته). |
| `content/tasks.ar.json` | نصوص المهام العلنية. |
| `content/stages.ar.json` | أهداف المراحل والتلميحات الثلاثة (حرفية من المنهج). |
| `content/glossary.ar.json`، `content/prepost.ar.json`، `content/mentor.ar.json` | المصطلحات، الاختبارين، معايير المرشد. |
| `private/answers.source.json` | **الإجابات الصحيحة** (خاص، لا يدخل `dist/`). |
| `private/secrets.json` | **رمز المرشد (PIN)** وأسرار البناء ورموز فتح المراحل (خاص). |

بعد تعديل أي ملف: `npm test` ثم `npm run build`. الاختبارات تتأكد أن كل مهمة تقبل إجابتها وترفض الخاطئة الشائعة، وأن الأدلة تطابق المفتاح.

### رمز المرشد وأسرار البناء

- يُنشأ `private/secrets.json` تلقائيًا أول بناء، وفيه `mentorPin` (6 أرقام). غيّروه من الملف ثم أعيدوا البناء.
- **احفظوا نسخة احتياطية من `private/` في مكان آمن** (ليس مستودعًا عامًا).
- **لا تغيّروا `checksumSecret` بعد بدء الورشة**، وإلا لن تطابق الرموز التي صدرت قبل التغيير.
- إن اخترتم `stageRelease: "code"` فرموز الفتح (للمراحل 2 و3 و4) في `private/secrets.json` تحت `unlockCodes`، وتُطبع أيضًا عند البناء. الموقع لا يحمل إلا بصماتها.

## 5. كيف تعمل الورشة

1. **قبل الورشة:** ابنوا ثم انشروا. انسخوا مجلد `dist/` على فلاشة وعلى جهاز المنسّقة (خطة احتياطية بلا إنترنت). انسخوا ملفات الأدلة (ZIP) وCyberChef المنزّل على الأجهزة.
2. **الفرق:** كل فريق يختار «جهاز الإجابات». التقدّم محفوظ على ذلك الجهاز. بقية الأجهزة تستعمل الأدلة وCyberChef.
3. **المرحلة:** يحل الفريق المهام، ثم يضغط «أنهينا المرحلة». إن كانت فيها بنود مفتوحة (المرحلة 1: الحكم النهائي. المرحلة 4: تبرير الترتيب والتقرير) تظهر «اطلبوا مرشدًا».
4. **المرشد:** يفتح `وضع المرشد` على جهاز الفريق، يدخل PIN، يقيّم، ثم «اعتماد التقييم وإصدار رمز النتيجة». بعدها تُقفل نتيجة المرحلة.
5. **الرمز:** يكتبه الفريق أو ينسخه إلى المنسّقة. شكله `1-T3-S2-14-1-3-22-XXXX` أي (الإصدار، الفريق، المرحلة، النقاط، التلميحات، الأخطاء، الدقائق، المجموع الاختباري). المرحلتان 2 و3 بلا بنود مفتوحة فيصدر رمزهما فورًا.
6. **اللوحة:** تفتح المنسّقة `board.html` (أو `#/board` من الموقع)، تلصق الرموز، وتختار أول وثاني فريق ينهي كل مرحلة للمكافأة (+2/+1 قابلة للتعديل). «عرض الشاشة» يعرض الترتيب فقط بخط كبير، وزر لإخفاء/إظهار التفاصيل. لا تظهر على الشاشة أخطاء ولا تلميحات ولا تنبيهات.
7. **الاختبار:** القبلي في البداية والبعدي في الختام، من رابطي `#/pre` و`#/post`.

### إن تعطّل الإنترنت أو الموقع

افتحوا `dist/index.html` من القرص (نقرتان) على كل جهاز. كل شيء يعمل بلا إنترنت. تنبيه: التقدّم محفوظ **لكل عنوان على حدة**؛ ما حُفظ على الرابط المستضاف لا يظهر في نسخة القرص. انقلوه بـ «تصدير التقدّم» ثم «استيراد تقدّم» (الملف لا يتأثر بالعنوان).

### تعطل جهاز الإجابات

من الشاشة الرئيسية «تصدير التقدّم» (يُنصح بذلك بعد كل مرحلة)، ثم على جهاز آخر «استيراد تقدّم». يتحقق الاستيراد من الملف ويرفض ما عُدّل بالخطأ، ويطلب تأكيدًا قبل استبدال تقدّم موجود.

### بين البروفة والورشة

التقدّم يبقى في المتصفح. امسحوا بيانات الموقع قبل الورشة (Chrome: `Ctrl+Shift+Delete` ← «ملفات تعريف الارتباط وبيانات الموقع الأخرى» ← «كل الوقت»)، أو جرّبوا في نافذة خاصة. الاستخدام في النافذة الخاصة يعمل لكن التقدّم يضيع عند إغلاقها، وتظهر رسالة تنبيه.

## 6. جمع نتائج الاختبارين

القرار النهائي لم يُحسم، فالافتراضي: **كتلة نصية** (حوالي 10 أسطر) ينسخها المشارك ويسلّمها كما تطلبون. إن ضبطتم أحد الخيارين في `config/settings.json`:

- `RESULTS_FORM_URL`: يظهر زر «فتح نموذج الإرسال» يفتح نموذجكم الخارجي في تبويب جديد ليلصق المشارك فيه الكتلة.
- `RESULTS_ENDPOINT`: يُرسَل نص الكتلة تلقائيًا بـ POST (بلا قراءة الرد). **لم أجرّبه إلا مع خادم محلي**، ولا أتحقق من الاستلام؛ تبقى الكتلة للنسخ احتياطًا. هذا الخيار يرسل بيانات خارج الجهاز، فاستعملوه بعد موافقة المشاركين.

جمعتم الكتل في ملف نصي واحد؟ احسبوا النتائج:

```
npm run score -- results.txt
```

يطبع متوسط الفارق (عتبة المنهج 1.5 من 6) ونسبة من حصل على 4 فأكثر بعديًا (عتبة 70%)، ويكتب جدول CSV يفتحه Excel بالعربية. السؤالان B7 وB8 يُصحَّحان يدويًا من الجدول. **القياس لتحسين الورشة لا للحكم على فرد.** الاستبيان (8 أسئلة) وتصويت الاهتمامات خارج الموقع كما قررتم.

## 7. الحدود الصريحة

اقرأوها ولا تعِدوا بغيرها:

- **الإجابات الصحيحة مخزّنة كبصمات (SHA-256 مع ملح)، لا نصًا.** لكن الإجابات القصيرة («نعم»، «لا»، خيار من أربعة) قابلة للتخمين، وطالب تقني مصمّم يستطيع تجاوزها. هذا **رادع معقول لا أمان مطلق**. لا جوائز في الورشة؛ وإن أُضيفت جائزة، افتحوا بأنفسكم إجابات الفريقين الأولين قبل الإعلان.
- **رموز النتائج غير مضمونة ضد التزوير.** المجموع الاختباري يكشف الأخطاء العفوية (حرف خاطئ عند النقل) والتعديل البسيط فقط، لأن السرّ في كود المتصفح.
- **رمز المرشد (PIN) رادع بسيط** يمنع الدخول بالخطأ، وليس حماية قوية.
- **التقدّم محفوظ في متصفح كل جهاز** (`localStorage`). إن مسحه أحد ضاع (إلا ما صُدِّر). لا يوجد خادم يحفظ شيئًا.
- **الوقت المسجَّل** في الرمز هو من أول فتح للمرحلة إلى ضغط «أنهينا»، فقد يزيد إن فُتحت الصفحة مبكرًا. لا مؤقت ظاهر للفرق.
- **قيم النقاط والعتبات اقتراحات** لم تُجرَّب. جرّبوها في البروفة قبل الورشة.
- لا يرسل الموقع شيئًا إلى أي خادم افتراضيًا، ولا تحليلات، ولا CDN، ولا خطوط خارجية (خطوط النظام فقط). الاستثناء الوحيد الاختياري: `RESULTS_ENDPOINT` وهو فارغ.

## 8. ما يجب أن تجرّبوه قبل الورشة

هذه ليست مجرّبة من جهتي، وتحتاج جهازكم:

1. **SHA-256 في CyberChef المنزّل داخل المتصفح.** القيم حُسبت وتحقّقتُ منها بـ Python وNode فقط. جرّبوا عملية `SHA2` (حجم 256) على `RWD-KIT-A/0318/k3` بلا مسافة ولا سطر زائد، وقارنوا الناتج بالبصمة رقم 2 في ملف النشرة (07). جرّبوا أيضًا `From Base64` وXOR بالمفتاح `ufuq` (UTF8).
2. **المتصفحات والأجهزة الفعلية:** Safari على Mac، وهاتف أندرويد وآيفون. اختباراتي الآلية على Chrome بلا واجهة فقط.
3. **بروفة كاملة بشخصين** (مبتدئ ومتقدم) تقيس الزمن الفعلي لكل مرحلة، وتكشف الأخطاء في الأدلة.
4. **الشاشة والإضاءة في القاعة:** عرض الشاشة (`board.html#projector`) على الشاشة الفعلية.
5. **شبكة القاعة** والبطاريات والشواحن (الكهرباء أكثر ما يعطّل ورشة لابتوبات).

قائمة القبول اليدوية الكاملة في [ACCEPTANCE.md](ACCEPTANCE.md).

## 9. بنية المشروع

```
build.mjs            سكربت البناء (يولّد dist/ ويفحصه)
shared/              كود يعمل في المتصفح وفي Node: التطبيع، SHA-256، التصحيح، النقاط، التقدّم، الرموز، اللوحة، الاختبارين
src/                 الصفحات والواجهة (index.html وboard.html وjs/ وcss/)
content/             النصوص العلنية (مهام، مراحل، مصطلحات، اختبارين)
config/              الإعدادات (نقاط، إعدادات عامة، مرادفات)
private/             الإجابات والأسرار (لا يدخل git ولا dist/)
evidence/            ملفات الأدلة التسعة (لا تُعدَّل)
docs/                المنهج ودليل المرشد (لا يُنشران)
tools/               أدوات البناء والفحص والتصحيح
tests/               الاختبارات (node --test) واختبارات المتصفح (tests/ui)
dist/                ناتج البناء: هو الذي يُنشر
```

أوامر إضافية: `npm run review` (يولّد وثيقة مراجعة المحتوى الخاصة `private/REVIEW-C.md`)، `npm run demo` (صفحة اختبار الودجتات للتطوير فقط، تُبنى في `dist-demo/` ولا تُنشر)، و`npm run test:flow` و`npm run test:board` و`npm run test:prepost` لكل جزء على حدة.

## 10. تعديل المحتوى

1. عدّلوا النص العلني في `content/tasks.ar.json` والإجابة الصحيحة المقابلة في `private/answers.source.json`.
2. شغّلوا `npm test`: يفشل إن اختلف معرّف خيار أو خانة بين الملفين، أو إن ظهرت إجابة صريحة في النص العلني، أو إن لم تعد مهمة تقبل إجابتها.
3. `npm run build` ثم انشروا.

ملاحظات المرشد («سجّل ملاحظة» لإجابة رفضها الموقع ويراها المرشد صحيحة) تظهر داخل ملف «تصدير التقدّم» لتضيفوها لاحقًا إلى القائمة المقبولة في `private/answers.source.json`.
